## 结论

功能面已经不是“追平一个桌面壳”：DSH Studio 同时提供 Windows/macOS/Linux、轻量与完整
离线包、插件市场、受认证的手机远程、多 Profile、内置终端、多窗口、会话全文搜索、Token
与费用统计、会话导出、命令面板、崩溃/诊断恢复和受限插件协议。

当前真正的差距集中在三处：

1. **分发信任与触达**：系统代码签名凭据、外部包管理器首次提交、稳定镜像与社区触达。
2. **真机验收深度**：CI 能证明跨平台编译和 headless 行为，但不能替代 macOS 真机、签名安装、
   更新和系统集成验收。
3. **打包 UI 自动化**：已有完整逻辑覆盖和真实 Harness 启动门禁，仍需给最终安装包增加可重复
   的 WebView/窗口交互冒烟。

## 下一阶段：发布后继续完成

### P0 · 信任和真机

- **系统签名实证**：发布流水线已经支持 Azure Artifact Signing、Apple Developer ID、公证和
  stapler，但只有配置真实凭据并在正式产物验证通过后，才能宣称对应资产具有系统发布者签名。
- **macOS 真机矩阵**：至少覆盖 Intel 与 Apple Silicon 的首次安装、Gatekeeper、登录项、通知、
  目录选择、终端、完整离线版和应用内升级。目前没有 Apple 设备，不能把 CI 当作真机结论。
- **升级矩阵**：用最近两个正式版本分别覆盖轻量→轻量、完整→轻量、损坏更新清单、离线更新、
  更新后 Profile/插件/凭据保持。

### P0 · 分发

- 提交并维护 winget、独立 Homebrew tap、AUR；Flathub 只有在宿主开发工具边界解决后才对外
  宣称等价支持。
- 建立可验证的大陆镜像：只镜像原字节，独立同步 `SHA256SUMS.txt` 和签名，监测延迟与错误，
  不把临时 GitHub 代理写成官方渠道。
- 官网展示真实渠道状态、版本、架构、轻量/完整区别和校验方式；状态来自发布资产而不是手工文案。

### P1 · 最终安装包自动化

- Windows 安装包：安装→首次引导→运行时准备→启动→新建终端→切换三种展示面→重启→卸载。
- Linux AppImage/deb/rpm：WebKit 启动、PTY、文件选择、托盘与进程树回收。
- macOS：待真机和签名凭据具备后加入相同流程；在此之前保持“构建/单测通过，未真机验证”的标注。
- 把截图、WebView 控制台、Harness 尾日志和诊断包作为失败产物上传，不能只留下一个退出码。

### P1 · 插件生态

- 随下一次正式版本发布 SDK 与 Host Protocol 1 文档；增加第三方 fixture 仓库和兼容性测试模板。
- 后续为提供者发布机器可读健康回执。本地原生协议/延迟/可安装性检查已经交付；HTML 网站仍不能冒充安装 API。
- Host 协议只在真实用例出现时增加窄能力。包管理、任意命令和原生句柄不进入通用只读服务，
  需要修改的操作继续由用户可见的 Protocol 3 审查、一次性意图、回执与回滚控制。

### P2 · 产品深化

- 日期趋势、本地预算状态和防表格公式注入的 CSV 导出已经交付。
- 不携带凭据的 Profile 可验证备份/恢复预览已经交付。
- 键盘/表单/对话框结构门禁、减少动画、强制颜色，以及屏幕阅读器/200% 缩放人工矩阵已经交付；辅助技术真机运行仍属于候选版本验收。
- 提供可选、明确同意、可关闭的匿名可靠性指标；在隐私设计和数据保留规则完成前不接入遥测 SDK。

## 发布判定

未来一次版本只有同时满足以下条件才可发布：工作树和版本差异已审计；前端与 Rust 覆盖率门禁、
Clippy、生产构建、打包测试通过；完整运行时在三平台冷安装并真实启动；对应平台资产、更新签名、
SHA-256 与系统签名状态逐项核验；Release 说明只写由提交、测试和实际产物支持的更新与修复。
