# 支持与验证矩阵

这份矩阵区分自动化证据与平台验收。一次本地测试通过，并不代表所有桌面环境都已真机验证。

当前托管基线为 `@deepseek-ai/dsh@0.1.7-rc.2`。发布前，CI 会从空目录安装带完整性锁定的
依赖图，并启动一个需要认证的真实 Web Profile。

| 项目 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| Rust 与前端单元测试 | CI 与本地 | CI 构建目标 | CI 构建目标 |
| 隐藏子进程启动 | `CREATE_NO_WINDOW` 合同 | 原生进程路径 | 原生进程路径 |
| Harness 托管与就绪检测 | 自动化 | 自动化 | 自动化 |
| 包内前端字节 | MSI/NSIS 资源检查 | 挂载 DMG 后检查资源 | AppImage/DEB/RPM 解包检查 |
| Full 包内运行环境 | 发布 CI 使用包内 Node 启动认证 Profile | 发布 CI 使用包内 Node 启动认证 Profile | 发布 CI 使用包内 Node 启动认证 Profile |
| 安装升级与卸载 | 发布 CI 临时环境自动执行，覆盖上一版 Lite 和 Full | 仍需真机安装器验收 | 仍需系统包管理器验收 |
| 真机显示、睡眠唤醒、防火墙 | 需要设备测试 | 需要设备测试 | 需要设备测试 |

本地 Windows 打包预演只解包 MSI 资源，不登记安装。NSIS 的有状态安装、升级和卸载默认只在
GitHub Actions 临时运行器自动执行，也可在明确选择后于本地执行。单独的 `--smoke-test`
只能证明可执行文件可加载，不能证明 GUI 能启动。资源哈希、包内离线启动、真实 Windows
WebView 操作与真机验收属于不同证据。

发布资产先保留为草稿，构建矩阵、打包检查、完整产物/更新清单和校验和全部通过后才公开。
操作系统发布者签名及 macOS 公证仅在配置对应凭据后验证；必需的更新包签名是另一套机制。

## 报告问题

请附 Studio 版本、系统版本、所选 Profile、准确操作、时间戳和脱敏诊断导出。
不要附 API 密钥、配对凭据、主目录机密或完整环境变量转储。
