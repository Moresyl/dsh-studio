What the shell actually does

The harness is a command-line tool that can run shell commands on your machine. Most of the work here is in treating that seriously: supervising it, containing it, and keeping it off the network.

SupervisionRestarts before you notice

A crashed harness comes back with an increasing backoff rather than a tight loop. The shell also probes it over HTTP every ten seconds and recycles the process after three consecutive misses — a hung server and a dead one look the same from the outside.

ContainmentNothing outlives the window

Every child joins a Windows job object, or a POSIX process group. Closing the shell reclaims the whole tree, including the grandchildren that a plain kill would orphan and leave holding a port.

ExposureLoopback, with a safe port policy

The harness uses --port 0 by default and reads back the kernel-assigned port. You can instead save a fixed port from 1024–65535; conflicts are reported before Node starts. It always binds 127.0.0.1 and nothing else.

SetupNo prerequisites to read about

No Node.js on the machine? The shell fetches a runtime for it, verifies it and keeps it beside the app. Then it installs the harness itself. A first run is a button, not a page of instructions.

PluginsA marketplace, in the window

Search the npm registry, read what a plugin does, install it, and turn it on or off again — without a terminal and without restarting the harness by hand.

HandoffYour phone, paired by QR code

Point a camera at the window and carry the session to your phone over your own network. Pairing codes are one-use and expire in two minutes, and the harness itself never leaves loopback — a separate gateway is what listens on the LAN.

Check what you downloaded

Worth doing for anything that runs shell commands on your behalf, and doubly so for a file that came through a mirror.

Compare the checksum

Every release carries a SHA256SUMS.txt covering every file on it, written by the same workflow that built them. 

sha256sum -c SHA256SUMS.txt --ignore-missing
Get-FileHash .\DSH.Studio_*_x64-setup.exe

Updates are signed

Each installer and archive ships beside a detached signature. The app verifies it against a public key compiled into the binary before it will apply an update, so a tampered file is refused rather than installed.

Built where you can watch

Installers are produced by a public GitHub Actions workflow from a tagged commit — not uploaded from anyone's laptop. The workflow file and every run's log are readable.
